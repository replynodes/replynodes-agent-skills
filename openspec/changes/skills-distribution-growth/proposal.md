# Proposal: Legitimate skill distribution growth

## Why now

The canonical repository has useful public skills, but external indexes currently show nested-discovery friction, stale slugs/descriptions, and ClawHub attribution gaps. We need a measurable, policy-safe acquisition funnel rather than more listings or synthetic activity.

## Scope

- Make canonical focused and umbrella install commands explicit and testable in clean environments.
- Improve truthful task metadata and first-screen CTAs for `company-research`, `url-to-markdown`, and `app-store-api`.
- Add five useful GitHub Action examples that lead developers to canonical installs without running install loops.
- Define a 30-day baseline separating external registry counters, discovery visibility, GitHub traffic, downstream callers, conversions, and retention.
- Record Skills.sh/find-skills/ClawHub behavior and upstream-owner actions without claiming unsupported registry provenance.

## Out of scope

- Artificial installs, duplicate listings, leaderboard manipulation, or misleading growth claims.
- Registry writes or slug renames without owner/operator approval.
- New analytics sinks, credentials, private-data access, or write-capable fetcher behavior.

## Capabilities

- `install-discovery`
- `distribution-measurement`
- `workflow-examples`
